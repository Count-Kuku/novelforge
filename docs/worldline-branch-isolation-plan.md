# 对话工作台多世界线隔离实施规划

> 状态：**2026-09-08 本轮 A–D 实现及独立代码复核完成**。实际契约、后续边界与验证记录见第 13 节及故事副本规划。
> 第 2、11 节保留开发前的代码基线及问题依据，不代表修复后的当前行为。新增结构已进入 schema 21–23，尚未主动迁移用户实际数据。
> 依赖规划：[每故事独立资料副本与双导入入口](./story-fork-library-plan.md)。先共享版本化资产/来源身份基础，故事级知识采用独立物化副本，分支级继续采用固定快照与本线增量，二者不是同一个操作。

## 1. 推荐方案与产品规则

采用 **独立分支身份 + 分叉点不可变快照 + 本线增量覆盖 + 全入口强制过滤**。

用户界面称“世界线”，代码新增 `branch_id` 表示创作连续性。保留既有 `worldline_id` 的来源世界语义，`version_scope` 继续表示 canon / project_main / au，不承担分支编号或深度。

第一版规则：

- 每个故事有默认主线；世界线属于故事，可跨会话延续。
- 一个会话固定属于一条线，切线进入该线的会话，不修改已有会话归属。第一版新分支只开放一个活动创作会话；历史主线多会话保留。
- 普通候选的反复修订留在同一条线，不每次调用模型都创建新线。
- 从已确认片段选择“从这里创建世界线”，创建有名称、来源和分叉点的新线。
- 从较早片段试写另一种后续也走分叉动作，不能只移动前沿后把新事实继续写回原线。
- 新线继承分叉点的正文与有效知识，此后的事实、章节、摘要独立增长。
- 父线后续修改不自动同步。首版固定已绑定的共享资料版本；显式差异预览与基线更新在 E 阶段提供，不作为首版已有入口。
- 第一版支持命名、切换、来源查看和归档；自动合并、设为正式主线、永久删除不纳入首版。

例：F1 中角色仍活着，从 F1 分出 B。主线 F2 写角色死亡，B 的 F2 写角色获救。两线各自提炼、检索和保存章节，允许两个不同状态分别成立。

## 2. 开发前代码基线与关键约束

以下路径除 storage 外均位于 `novelforge/` 下。

## 3. 数据模型

### 3.1 两个独立维度

| 维度 | 含义 | 例子 |
|---|---|---|
| project / story | 项目及独立故事 | 故事甲、故事乙 |
| worldline_id（现有） | 来源世界或既有设定连续性标签 | 原著甲、原著乙、main |
| branch_id（新增） | 本故事的创作走向 | 主线、获救线、黑化线 |
| version_scope（现有） | 知识来源/覆盖层 | canon、project_main、au |

获救线可以同时引用两部原著，不能让一个字段承担两个选择。首版不批量重命名旧 worldline_id，通过分支参考基线明确绑定来源世界与修订。

### 3.2 世界线结构

SQLite 仍为结构化事实源，正文继续使用登记的文件资产。

| 拟增表或关系 | 内容 |
|---|---|
| `story_branches` | branch_id、story_id、name、parent_branch_id、fork_fragment_id、fork_checkpoint_id、head_checkpoint_id、revision、status |
| `branch_checkpoints` | 不可变状态版本：父版本、正文前沿、快照清单 hash、基线版本、ready 状态、创建原因 |
| `branch_checkpoint_items` | checkpoint 到知识/来源/正文/配置精确修订的清单，完整保留关系、时序、可见性及删除覆盖 |
| `branch_fragment_states` | 本线片段成员、采用状态、顺序、章节汇编记录，区分继承和本线片段 |

会话、轮次、片段、消息和动作账本增加明确 branch 归属；session 保留本会话草稿前沿，跨会话有效状态以 branch checkpoint 为准，避免两处字段互为权威。

知识、待审核、实体、别名、关系投影、检索文档、反馈/冲突裁决、附件绑定、创作提醒和章节资产，补齐 branch 所属或可见性绑定。高频过滤/关联字段独立建列，不能仅放 tags 或 metadata。

约束：

1. branch 为不透明稳定 ID；数据库联合约束与 repository 校验共同阻止跨故事引用、循环引用和非法祖先前缀。
2. 故事内容 branch 必填；项目共享资料须有显式类型和绑定，空 branch 不等于所有分支可见。
3. 实体物理身份加入 branch 隔离域，保留 origin_entity_id / origin_knowledge_id 用于继承匹配。不同来源世界的同名实体不能直接合并。
4. 修改继承事实创建本线副本，关系端点映射到本线有效实体；别名合并、时序取代不能改祖先行。
5. 现有 `knowledge_revisions` 不能直接视为完整历史状态：`_apply_supersession` 会直接改旧行有效期而不为旧行追加修订，证据/关系也有独立投影。B 阶段先提供完整、不可变的有效状态快照及历史资产读取，再允许分支清单引用；不能只保存知识 ID 再读取可变当前行。
6. 新快照是不可变历史，不是第二套可编辑知识库。引用中的旧知识、来源原文和正文版本必须保留，清理不得破坏后代。

## 4. 分叉继承与知识覆盖

### 4.1 固定快照

禁止读取“当前线 + 所有祖先线的最新知识”。父线在 F2 的死亡事实不能进入从 F1 分出的子线；父线后来编辑、删除旧事实也不能改变子线。

分叉时固定以下清单：

- 分叉点之前有序的已确认正文前缀及内容版本。
- 该点完整有效知识修订，包括当时有效的事实、关系与别名。
- 绑定资料的来源世界、来源修订及可见片段。
- 创作配置、设定类提醒及允许继承的附件绑定。
- 可复用摘要的准确覆盖边界。

首版以显式清单引用不可变修订实现写时复制，不复制整个项目数据库；待有真实规模数据再优化清单存储。

### 4.2 检查点与迟到提炼

- 正文确认、知识提交/编辑/删除和基线更新形成有顺序的状态版本；使用事务内递增 revision 与精确修订 ID，不能只按时间戳或 chapter_no 截断。
- 正文确认事务固定 `base_checkpoint_id + frontier + accepted_content_hash`；迟到提炼只向该锚点附加获准的事实结果，再封存新快照。不能在提炼结束时读取最新分支 head 作为旧片段快照，否则期间 F2/F3 的事实会流入 F1。期间的手工改设定形成后续版本，若要应用旧锚点必须显式选择。
- 可分叉锚点记录全量可见状态清单，不能用经过 Token 裁剪的模型上下文快照替代。
- “正文已确认，记忆处理中”允许继续展示，但其可分叉检查点尚未 ready。
- 首版从该点分叉需提炼完成，或用户明确选择“跳过本次提炼并建立检查点”；跳过状态进入快照。
- 已冻结清单不随迟到结果变化；补提炼属于父线新状态，子线必须显式导入。
- `extraction_status=completed` 不等于知识已全部确认。检查点分别记录提炼完成、已确认知识、待审核候选和跳过状态；只有已确认条目进入有效知识清单。待审核不强迫用户停写，也不自动成为子线正式知识。
- 较早分叉点使用当时可靠检查点，没有历史快照时不能拿今天的知识伪装成当时状态。

### 4.3 有效知识

`有效知识 = 固定继承基线 + 当前线新增/覆盖/删除标记`

- 位置、存活状态等替换槽位只更新本线有效值，保留本线历史，祖先不变。
- 自由创作新增 `narrative_anchor`（本线片段/事件位置）与 `recorded_revision`（系统提交顺序）两个维度；章号仅作展示和章节关联。当前 `_apply_supersession` 对无章号或同章号不取代旧事实，不能直接复用为片段状态演进规则。修改历史片段设定与推进到下一片段必须明确区分。
- 追加槽位按稳定来源身份合并；删除继承条目使用 tombstone，避免刷新后复活。
- 同线“先存活、后死亡”保留时序；无法确定是进展还是矛盾时继续人工审核。
- 先按本线可见性和显式覆盖确定候选，再处理 canon/project_main/au 来源优先级；祖先高优先级不覆盖用户明确的本线修订。
- 分叉不自动把继承事实全部重新提炼。
- 提炼命中继承实体时保存已验证的 `target_origin_entity_id` 和具体来源世界；本线新实体分配独立身份。存在两部原著同名角色时要求消歧，不能继续仅按 name/profile.worldline_id 推导。实体物理 ID 与跨层匹配身份分开，既有 canon→story 覆盖链通过显式映射保持兼容。

共享正文内容不可变，采用、移出作品、定稿属于本线成员状态。汇编记录保存有序来源片段版本，避免反复保存时重复追加祖先前缀。

## 5. 统一读取与上下文

拟新增 `resolve_branch_context(...)`，返回只读范围：

`story_id + branch_id + checkpoint_id + frontier_id + baseline_revision + visible_revision_manifest`

生成、预览、知识校验及阅读投影共用此范围。route/session/fragment 的归属必须一致；profile 仅提供默认值，不能覆盖已绑定分支。

| 路径 | 隔离要求 |
|---|---|
| 正文与消息 | 当前线正文链、消息和获准的祖先前缀，动作回执也按线筛选 |
| 摘要与查询 | 摘要绑定 branch 和前沿 hash；覆盖超出分叉点就丢弃并重建 |
| 优先设定、实体聚焦、别名 | 先解析有效知识，不允许全库合并后过滤 |
| 词法/FTS/向量 | 每路 top-K 前过滤可见修订，融合后再校验 |
| 父段、相邻片段补全 | 继续校验来源修订、分支及分叉边界 |
| 图谱/时间线/实体详情 | 端点、边和事实各自校验，保留来源世界身份 |
| 附件与研究 | 文件可复用，可见绑定和提炼结果按线隔离；仅下一轮附件不自动继承或跨线消费 |
| 规则与提醒 | 设定性约束随检查点固定，一次性提醒按线消费；模型/费用等运行设置不充当故事事实 |
| 章节、审阅、作品 | 默认本线；“全部世界线”仅用于浏览，不进入生成上下文 |

branch 过滤不受现有 worldline prefer/strict 选项控制。缺身份时报错；少召回时可词法降级或返回无证据，不能跨线补结果。

资料共享与剧情隔离独立：项目原著/参考资料及其通用知识可供多个故事绑定，各故事再选择具体修订；故事/分支派生事实默认私有。提炼结果的使用范围不得大于来源的可见绑定。会话/单轮资料若要沉淀为故事长期知识，必须有显式提升动作，不能借后台整理自动扩大范围。不要把所有“导入知识”一律改成分支私有，也不要把全部项目库自动注入每个故事。

双入口以最新代码为准：“＋资料”默认 story，也可选择 project；资料库固定 project；两者自动提炼，原文只用于查证。项目导入不自动给 URL 中的故事绑定；通过“用于当前故事”显式创建副本。分支启用后 story 导入和正文提炼必须绑定提交时 branch。

缓存键、上下文指纹、检索反馈与冲突裁决包含 branch/checkpoint/baseline。索引滞后时由权威可见清单剔除过期项，准确读取降级或提示处理中，不能使用已覆盖旧事实。

历史来源必须有按 `source_revision_id + content_hash` 读取实际正文的路径。当前外部源索引从可覆盖的活动文件取正文，长资料批次的来源修订也不保证包含全文；因此仅过滤 revision ID 不足以恢复旧内容。新增不可变正文资产或有完整正文的修订读取器，索引这些历史版本；引用清单不能落回当前路径。

故事生成正文的共享来源也必须按片段范围限制，不能放行整篇文件后通过原文泄漏未来剧情。原著全文是否允许未来情节属于另一项资料策略，不能把分支隔离宣称为完整防剧透。

## 6. 写入、异步与并发

1. 操作启动时事务绑定 branch、checkpoint、fragment/content_hash、operation_id 和期望 revision。
2. 模型调用在事务外执行，模型不得决定可信归属字段。
3. 提交时校验归属、内容版本、取消/归档状态和期望 revision；同线陈旧结果不能覆盖新状态。
4. A 的操作运行时切到 B，结果仍进入 A 或因冲突失败，不随 UI 当前选择改变。
5. 首版同线影响正文/知识的写操作串行或 CAS 拒绝陈旧提交；不同线独立执行。
6. 提炼、自动审核、手工确认、撤销、重提炼及后台附件知识化都绑定原分支；幂等键包含分支、来源版本及提炼版本。
7. 审核比较本线有效知识与本批候选；兄弟线差异不互相阻塞，继承事实仍参加本线检查。
8. fork 原子保存分支、快照引用、前缀成员和新会话；幂等重试不重复建线。较慢的准备在事务外进行，提交再校验父 revision。
9. 沿用动作确认协议；本线撤销产生新修订，跨线导入是明确的新动作。

这批工作不宣称所有 SSE 生成具备跨进程恢复；完整 durable generation 可另立任务，但来源归属和失败状态必须可追溯。

## 7. 前端、章节与规划台边界

四个主入口不变，世界线选择器放在故事上下文旁。

- 对话片段菜单新增创建世界线，展示分叉点和继承说明；普通草稿仍沿修订—确认—续写循环。
- 会话列表默认当前线；刷新、直接链接、作品回跳携带 branch/session，不被“进入最近会话”逻辑覆盖。
- 资料库默认本线有效知识，标注继承/本线新增/本线覆盖。修改继承项创建本线修订，待审核同样按线过滤。
- 作品显示归属，同章号可共存，详情、删除、导出、回跳均保留分支。
- 设置提供名字、来源和归档；归档隐藏入口但保留后代依赖，首版不开放硬删除。

章节身份升级为 `(story_id, branch_id, chapter_no)`，文件路径、逻辑键、资产 ID 同步区分分支。保存、读取、追加、删除、审阅和上下章检索一起改，并记录来源片段版本。使用资产服务及可补偿写入保持数据库与文件一致，不能只给列表加过滤。

规划台旧接口显式映射默认主线；未接入分支的规划生成/章节写接口拒绝非主线目标，不能静默落到旧主线路径。规划台完整多线界面可后续扩展。

## 8. 迁移与历史限制

当前最高 migration 为 020；实施时从届时下一个连续版本新增，不修改历史 SQL。

1. 每故事建立默认主线，旧会话、片段、故事知识、章节和动作回填主线，保留已有来源 worldline_id。
2. 分类项目参考资料与故事派生内容；归属不明项列出报告，阻止自动进入新分支基线，等待人工指定。空作用域不能解释为共享。
3. 旧互斥设定不会自动被修复；按 fragment/source_revision 辅助追溯，不按标题、时间戳猜分支。
4. 当前主线核查后建立迁移检查点。旧片段缺可靠历史快照时仅支持“以当前设定创建变体”，明确不等于还原当时；精确历史分叉需重建并审核。
5. 发布后为新锚点持续建立检查点，保证以后可从较早片段准确分叉。
6. 重建实体/图谱/检索投影，维护别名、反馈与证据关联；变更实体 ID 必须保存映射，用户修订/裁决不能当缓存删除。
7. 祖先归档、会话删除和清理不得级联破坏后代快照；引用保留机制纳入生命周期服务。
8. 旧 API 缺 branch 时由兼容层解析主线或会话唯一归属，再调用 branch 必填核心服务；显式归属冲突直接拒绝。
9. 备份数据库和文件资产；迁移失败回滚，新索引就绪前不开放分叉。版本回退用一致备份恢复，不能降 schema 后继续写旧程序。

## 9. 实施顺序与发布门槛

| 阶段 | 内容 | 验收门槛 |
|---|---|---|
| A：现有循环收口 | 草稿同步、失败重试、采用/提炼状态、旧入口规则 | 生成—修订—确认—续写稳定，普通修订不误建分支 |

| C：隔离闭环 | 快照、固定继承、知识覆盖、异步归属、摘要/附件与全入口过滤 | 父线变化不污染子线，迟到任务和旧索引不串线 |

与故事副本工作协调：先交付故事副本规划 L0–L3 的导入规则、版本化资料及独立故事知识；本方案 B 复用这些基础，C 再建立分叉点继承。多世界线接入由本方案 C/D 交付，不另造一套快照或范围过滤服务；故事副本 L4 保留为后续版本更新和差异比较。若旧故事尚处 legacy 读取模式，先完成显式资料绑定迁移，再允许创建新世界线。

domain 提供纯可见性/覆盖规则；service/repository 管理分支、检查点及有效知识；workflow 编排 fork/生成/提炼；Vue 只负责输入呈现，不自行决定知识可见性。

### 11.1 当前同项目跨故事的资料共享事实

| 入口/内容 | 当前原文可见性 | 当前提炼知识范围 |
|---|---|---|
| Vue 资料库批量上传 | ResearchView.uploadBatch 显式传 project，附件清空 story/session；可跨故事召回，仍受检索任务/来源过滤 | 后台固定 reference 并回退 default，不能承诺在各个非 default 故事里共通，这是作用域传递缺口 |
| API 的 story 级附件导入 | 当前故事 | 非 canon 候选属于该故事 |
| 会话“＋资料” | client 默认 session，当前会话使用，原文不自动跨故事 | 提炼构造后是该故事知识，缺 session 限制，可能影响同故事其他会话 |
| 按 canon 原著流程提炼 | 取决于原文导入绑定 | 构造器明确 setting_scope=project，清除 story_id；正式确认后可供同项目多个故事引用，具体召回受来源世界等配置影响 |
| 对话已确认正文提炼 | 正文属于所在故事/会话 | 当前故事知识，不自动供其他故事使用 |

`scope=project/canon/reference` 在知识与来源模型中也表达资料性质，不能与 `setting_scope` 或 attachment.scope 的共享范围混为一谈。资料库列出条目也不意味着当前生成实际使用它；生成还经过 story/session/worldline 与任务检索条件过滤。

共享 canon 是同一份项目知识，不是每故事自动拥有一个可随意修改的副本。完整“共享库 → 每故事 fork”仍见 `story-fork-library-plan.md` 的后续规划；普通编辑共享条目会影响之后读取该条目的其他故事，故事独立改写需明确写入故事覆盖层。

### 13.1 2026-09-08 实现复核补充

本节保留实现复核时通过实际调用链暴露的验收要求；本轮处理结果与验证记录见第 13.3–13.4 节。

- **历史检查点与本线当前状态分开读取**：历史检查点保持不可变；本线当前状态允许编辑、删除和新增。重复读取历史检查点不能重新混入当前事实，也不能用历史检查点覆盖本线已提交的编辑或复活删除条目。再次建立子线检查点必须保留其有效继承资料。
- **接受正文和捕获基线同一事务提交**：不能先提交接受状态，再另开事务捕获检查点。隐式接受上一片段的续写路径也遵循同一规则。提炼晚于后续片段完成时，封存该基线及仅属于该片段的已确认提炼结果，既不能遗漏本片段知识，也不能带入后续知识。
- **归属保护落实到存储层**：旧调用省略 branch 时解析真实默认主线并校验状态；已有 knowledge_id/pending_id 不允许改为另一故事或世界线。归档线的读操作保留，写入与删除拒绝；其他线遗留待确认知识不能阻塞当前线的正常事务。
- **知识中心和生成采用一致的有效集合**：搜索、实体、关系、详情、证据、修订及待确认操作传递故事与世界线。继承知识通过本线副本或覆盖记录编辑，不能仅把父线记录设为只读就视为独立副本已完成。
- **兼容性也须执行真实流程验证**：生成完成、采纳、确认知识、预览复用、保存章节、复制故事和归档都纳入回归；前端接口模拟通过不能代替真实服务和 SQLite 事务验收。

### 13.2 第二轮代码审查收口要求

- **片段事实按正文祖先链取代**：同章与无章号的片段不能依赖任务完成时间；迟到的旧片段不能覆盖新片段。同一前沿的候选和兄弟片段不推断先后。当前可见集排除已被其中后继取代的事实，历史前缀仍保留当时有效事实。
- **配置分开保存历史和当前值**：旁支继承冻结配置，本线通过独立配置记录编辑；主线已有设置入口继续有效。显式主线参数与省略参数不能形成互不读取的两份配置。导演注的使用次数在所属线消费，保存、续写和再次分叉读取同一有效配置。
- **界面切换与直达恢复区别处理**：打开会话链接时恢复其归属线；用户主动切换故事/世界线时离开旧会话。过期会话请求不能把用户选中的新线切回。验收同时覆盖直接链接、下拉切换和请求乱序。
- **实体卡与关系图读取冻结内容**：仅按可见知识 ID 过滤实时实体表还不足以隔离父线修改；卡片正文、别名和关系都从本线有效知识快照构造。明确打开旧知识 ID 仍可查阅其历史。
- **对话动作包含执行、取消与撤销**：动作从会话固定归属取得目标线，配置更新、知识编辑、检索及保存章节均传递该归属；继承知识的修改创建本线副本，撤销不能写回父线。

### 13.3 最终实现边界

- migration 021 建立世界线、检查点及片段状态，022 提供公共资料发布版本和故事绑定，023 将实体唯一身份扩展到分支。原有来源 `worldline_id` 保持原义，默认主线 ID 保留原故事 ID 的大小写、符号和中文。
- 不可变快照保存有效知识正文、实体/别名/关系、证据、来源及配置；生成、知识中心和快捷查询都读取冻结内容，不能只过滤 ID 后再取父线最新行。当前线的新增、修改、删除通过本线状态覆盖，历史快照不随之改写。
- 资料导入在创建原文文件之前解析会话归属，批量导入在提交时固定同一个目标分支。后台批次、任务、待审核知识和确认结果沿用该归属；项目导入不带私有故事/分支。
- 同名多源实体先选择来源再确认。关系的起点、终点分别选择，第一端选择后仍有歧义时继续待审核；明确的新实体可在当前线创建。模型自报的来源、解析状态和覆盖 ID 不能代替服务端校验。
- 关系快照按所属知识 ID 收集图边，并冻结没有独立角色条目的端点；普通资料行不能覆盖已补全的图投影。持有者、成员等引用字段仅在冻结来源唯一时生成旁支图边；歧义或未知引用保留文字，通过明确的关系条目完成来源选择后再建立关系，首版不猜测同名实体。
- “提炼完成”只表示提炼过程结束，未确认候选仍不进入正式知识。跳过提炼形成明确标记的检查点；未完成/失败状态不能伪装成可靠历史快照。
- 当前线配置可编辑并继续用于生成、导演注消费和再次分叉；主线显式参数与旧省略参数读取同一配置。关系图、作品和章节各自保持分支归属。
- 暂未提供规划台完整多线编辑。其工作区、结构与讨论接口遇非主线目标明确返回 409；已支持的对话配置、上下文预览及章节接口继续接受分支参数。
