# 每故事独立资料副本与双导入入口规划

> 状态：**2026-09-08 本轮 L0–L3 实现及独立代码复核完成**。保留另一窗口的导入入口修改；实际使用规则及验证记录见第 12.2–12.3 节。
> 用户目标：同项目资料可以复用，每个故事对设定的修改互不影响；日常只需理解“＋资料”和“资料库导入”。
> 本文替代原“零 schema 改动、直接复用故事复制”的初步构想。第 3 节保留开发前基线；资料版本与副本结构已进入 schema 22，与世界线 schema 21/23 配合。

> 2026-09-08 补充：正在执行实现后复核。验收覆盖完整发布快照、正文来源、关系端点、实际生成复用，以及整故事复制；历史审查中的旧行为不代表本轮最终设计。

## 1. 最新导入契约（覆盖此前讨论）

用户已在另一窗口修改导入入口，本轮保留这些修改：

| 入口 | 当前及本轮继续保持的规则 |
|---|---|
| 对话“＋资料” | 文件/粘贴共用 MaterialImportForm，默认归属当前故事，可明确选择项目；保存后自动提炼 |
| 资料库“导入资料” | 文件/粘贴固定项目归属，保存后自动提炼；不显示网页导入或研究管理面板 |
| 原始资料 | 用于来源查证；普通创作上下文使用已确认知识，不重新放开原文 RAG |
| 共享到项目 | 已确认且来源合格的导入知识可显式复制到项目；保留故事原条目，不搬移、不重提炼 |

当前 target_scope/story_id 已贯穿批次、任务、提取、整理、repository；资料性质和知识所有权分开，项目知识不再回退 default。verify_knowledge_ownership 已通过。对 legacy session/turn 附件仍保留兼容数据，但新 UI 不再创建它们。

因此撤回旧规划“＋资料仅会话”“＋资料默认不提炼”“保存后原文立即用于写作”三项建议。新代码不得为符合旧规划倒退用户刚完成的入口重构。

故事副本通过资料库的“用于当前故事”创建，项目导入本身只创建公共知识，不能因为 URL 携带 story_id 就隐式写入该故事。新故事可以选择公共资料，也可以稍后添加，不强制建故事向导。

## 2. 独立副本的明确语义

项目保存公共原文和已整理知识的不可变发布版本。故事 A、B 各自从选定版本建立独立副本：

- A 改名、改人物状态、删除设定，不影响 B 或项目资料。
- 项目资料后续修正、重提炼，不自动覆盖 A/B 的现有副本。
- 同一故事可使用多份资料/多部原著；同名角色保留来源身份。
- 删掉 A 的副本或删除 A，不删除公共原文，也不影响 B。
- 重复点击“用于当前故事”不会重建副本或重置故事已有修改。
- 已确认的资料知识可以直接复制，不为每个故事重复调用提炼模型；复制行为追加自己的来源记录，不伪造原知识的审核历史。
- 用户不必新建故事才能使用副本；已有故事可随时添加资料。

独立的是可编辑知识、资料使用状态和后续故事设定。原文二进制/长文本可复用同一不可变资产，不需要为每个故事复制整份 PDF/小说。

## 3. 开发前可复用点与限制

| 代码 | 已有能力 | 使用限制 |
|---|---|---|
| `services/memory/story_lifecycle.py::create_story` | 建故事、目录与元数据事务 | 当前不选择资料、不复制知识；新增服务编排，不把 LLM 调用塞进创建事务 |
| `domain/setting_knowledge.py::copy_setting_items` | 复制优先设定并记录来源 | 仅 core_only；重复调用可能覆盖本地修改；按分类分次保存，不能直接承担完整知识库绑定 |
| `storage/repositories/story_copy.py::clone_story_storage_rows` | 复制故事资产、工作流和会话，重映射部分 ID | 是故事→故事复制，不是项目资料→故事知识复制，没有完整共享知识/实体/证据复制契约 |
| `storage/repositories/entity_identity.py` | 根据故事、来源世界等形成实体隔离域 | 物理身份隔离不等于查询自动隔离；还需稳定来源映射、关系端点与别名处理 |
| `storage/repositories/entity_query.py::merge_worldline_baseline` | 合并项目 canon 与故事事实 | 会读取项目当前知识；故事层只接 project_main/au。原样复制 story+canon 会被该入口遗漏 |
| `services/retrieval/search.py::_story_scope_allowed` | 限制故事/会话原文可见性 | 项目数据默认可见，还需绑定白名单和精确修订过滤 |
| `storage/repositories/knowledge.py` | 知识写入、修订与图谱投影 | 旧事实有效期有原地更新；不能把现有修订 ID 等同于完整历史状态 |
| `storage/repositories/stories.py::purge_story_scoped_rows` | 清理故事数据 | 新绑定、来源引用、后代检查点需一起维护，避免删掉共享依赖 |

除 storage/frontend 外，上表路径均位于 `novelforge/`。

原稿“隔离免费”“零 schema 改动”“直接复用 clone_story_storage_rows”三项结论撤回；只能复用底层事务、ID 映射和知识写入能力。

## 4. 推荐实现：知识先做真实副本，原文共享固定版本

首版将选定的已确认知识物化为故事自己的 knowledge_items，使用新的 knowledge_id，并维护来源映射。这样可以继续使用既有编辑、审核、修订和关系投影服务。

不在故事级额外构建一套完整的延迟写时复制引擎。多世界线从分叉点共享不可变历史快照并叠加本线变更，按另一份规划实现。两者共用版本化资产、来源身份映射和有效上下文服务。

### 4.1 资料版本与副本结构

| 结构 | 主要字段/职责 |
|---|---|
| `reference_libraries` | library_id、项目、标题、资料身份；单文件可直接成为一个资料条目，多文件归组后续扩展 |
| `reference_library_releases` | release_id、library_id、版本、状态、内容 hash；immutable、ready 后不可修改 |
| `reference_library_release_items` | 精确来源/知识修订清单，证据、实体身份与关系映射；公共知识修正生成新 release |
| `story_library_bindings` | binding_id、story_id、branch_id、library_id、release_id、状态、创建操作；同故事同世界线同资料一个活动绑定 |
| `story_library_item_links` | binding_id、origin_knowledge_id/revision_id、origin_entity_id、local_knowledge_id、导入基线 hash、修改/删除状态 |

来源正文使用多世界线规划要求的不可变资产读取；release 清单复用同一快照基础，不另外维护第二份可编辑知识库。

知识副本写入 `setting_scope=story` 和目标 story_id，保留来源 worldline_id、真实权威和证据。绑定范围与资料性质分开建模；“项目共享”不等于“官方原著”，不得为实现共享把普通参考资料标成 canon。

已有 `version_scope` 保存来源含义；读取层通过绑定成员识别资料副本，不再只用 project_main/au 判定所有故事知识。不要为了绕过旧过滤器把整个原著改标成用户原创设定。

### 4.2 身份与关系

- 唯一绑定成员键包含 binding 与稳定来源知识身份；首次复制建立 local ID，幂等重试复用，不能按名称覆盖。
- 来源实体 ID 与故事实体 ID 分开，保存显式映射；关系、物品持有、事件参与、别名都通过映射写入目标故事。
- 两份资料同名实体不直接合并；来源判明是同一对象时才显式关联。知识有多个证据来源时以 release 成员清单为准，不仅按一个 source_id 或标题筛选。
- 本故事删除资料知识保留删除状态和来源链接，重复绑定不让它复活。
- 实体、关系、证据及完整有效时序均纳入快照；复制旧状态不能通过当前源库的可变投影反向读取。

## 5. 两个入口与副本衔接

### 5.1 “＋资料”

1. 提交时固定项目、目标故事、选择的 story/project 所有权；多世界线启用后故事资料还固定当前 branch。
2. 按当前实现保存来源并启动后台提炼；界面区分处理中、已确认、待审核、失败、费用待确认，不把原文保存完成等同知识生效。
3. story 结果只属于提交的故事/分支；project 结果成为公共可用资料。切换 UI 不改变后台目标。
4. “共享到项目”保持现有复制语义；只能处理合格导入知识，不自动发布故事正文提炼事实。

### 5.2 “资料库导入”与“用于当前故事”

1. 文件和粘贴固定 project，自动提炼并审核，原文仅作为证据。
2. 展示已确认的项目资料，按可靠的 source/evidence 与原始附件归组，不仅按标题匹配；没有合格知识时说明仍需处理/审核。
3. 用户选择“用于当前故事”，原子创建来源版本、绑定及知识副本；不再调用模型。项目知识与证据保留。
4. 新版公共知识只提示更新，不覆盖旧副本；重复使用返回既有绑定，保留故事修改。
5. 故事已有直接导入的私有知识继续有效，不要求先提升到项目再复制回来。

## 6. 生成只读取本故事有效内容

`resolve_story_reference_context(project, story, branch?)` 管理故事资料绑定；世界线上下文与知识中心在此基础上解析冻结快照和本线增量，供生成、实体聚焦、检索、图谱和来源预览使用。

返回当前故事已绑定资料版本、已物化知识副本及故事自建知识。原文只从独立证据查看路径读取，不进入普通生成。多世界线启用时，以当前 branch checkpoint 保存的版本为准，不跟随 story 当前可变绑定。

必须移除“总是叠加项目最新 canon”的隐式行为，否则删除/修改副本后原设定会再次进入上下文。无绑定的项目资料可用于人工浏览，但不能自动成为当前故事事实。

原文保留在查证路径，不直接进入普通创作。遇到“原文中死亡，本故事设为存活”时，已验证的故事覆盖必须在实体事实与普通检索装配中一致生效：可识别的冲突知识/段落剔除或标注为原著差异，模型看到明确的本故事事实。全文中隐含的自然语言矛盾不能仅靠 ID 过滤完全识别，不宣称能自动穷尽；覆盖命中和实际上下文纳入验收。

资料库提供明确的项目资料/本故事资料视角；本故事视角默认编辑私有副本。公共资料编辑需从明确标注的项目资料入口进入并产生新 release；普通改名/修改按钮不允许静默写项目库。

## 7. 事务、并发与异步

- 首版新增绑定使用 preparing/ready/failed/archived 状态，复制到一半的知识不可见；提交绑定、知识、来源映射及投影任务原子完成。
- 大清单可在事务外准备，提交校验目标 story/branch revision 和固定 release；发布版本已不可变，不能在复制过程中读取源库最新状态。
- 幂等键包含 story、library、release 和操作身份。重复初次绑定返回原结果；更新版本走独立动作，不能借重复导入覆盖修改。
- 任务在启动时记录目标故事与绑定意图；项目层提炼不再用 default 故事兜底，LLM 归因的“发起故事”与知识实际所有者分开。
- 解除绑定、归档故事与后台完成并发时校验状态；不得因迟到任务重新启用已移除资料。
- 模型调用和全文解析不放进 SQLite 长事务；索引失败可重试，但不得回退到未绑定项目全库。

## 8. 更新、解除与多世界线衔接

首版先交付固定副本，不自动同步。新版本仅提示“资料有更新”，可查看来源版本；完整更新并入后续阶段，采用旧基线/本地副本/新源版本三方差异：

- 本地未改且来源有新值：预览后应用。
- 本地已改或已删除：默认保留，冲突逐项选择。
- 来源删除：不直接删除本地自建或已改知识。
- 应用完成保存新的绑定版本和知识修订，旧快照仍可读。

解除“本故事使用”停止将该绑定的原文与资料知识放入上下文，不删除公共资料、正文或可追溯历史。用户自建事实不属于绑定成员，保留；已改副本若要继续使用需显式保留为故事自建设定，避免解除操作的含义不清。

与多世界线的关系：

`项目资料版本 → 故事独立副本/有效状态 → 世界线分叉快照 → 本线变更`

不实现两套重复快照/权限解析。先实现版本化资产与故事副本，再让 branch checkpoint 引用故事在分叉点的有效版本。分叉后，父故事主线新增资料或更新绑定不能自动进入旁支；资料库导入目标同时捕获当前 branch，仅更新目标线状态。

原文/知识修订的引用保留覆盖 story binding 和 branch checkpoint。归档公共资料只隐藏新绑定入口，不能清除 A/B 已使用的历史内容。

## 9. 迁移与实施顺序

开发前 migration 最高 020；本轮已新增连续迁移 021–023，当前 schema 为 23，不沿用原稿“零 schema”假设。

| 阶段 | 内容 | 完成标准 |
|---|---|---|
| L0：导入回归 | 保持新 story/project 双入口、自动提炼及知识提升，验证归属与原文不参与生成 | 两个入口的文案、原文使用和知识目标一致 |
| L1：公共版本基础 | 完整知识/关系快照、不可变原文、资料 release、来源身份映射 | 源资料更新不改变旧版本读取 |
| L2：故事副本闭环 | 绑定、知识物化、私有编辑/删除、统一读取过滤、幂等与失败恢复 | A/B 使用同资料，A 修改不影响 B/公共源，刷新后仍正确 |
| L3：用户入口与迁移 | 建故事可选资料、已有故事添加、状态展示、解除/归档、存量接入 | 普通用户只需理解两个入口和“用于当前故事” |
| L4：后续增强 | 显式版本更新、差异比较、跨线选择性接入新版本 | 本地修改和旁支快照得到保护 |

本轮实际交付 L0–L3，并完成多世界线规划 A–D；多世界线的完整分叉仍按其 A–D 验收，不能用故事副本替代分支隔离。

存量项目：

1. 已导入原文与正式知识按来源证据整理为项目资料条目；资料性质/归属不明的列出报告，不把故事生成事实提升到项目库。
2. 当前项目共享行为与新显式绑定不同。首次迁移提供一次性资料清单确认；确认前旧故事保持标注的 legacy 读取模式，新建故事使用严格绑定。不能静默切空知识，也不能声称未确认旧故事已隔离。
3. 目标明确的公共来源可建立固定副本；保留已有故事自建和覆盖知识，不用来源名称匹配覆盖。
4. default 误归属、会话知识扩散按原附件/来源/任务证据修复，无法唯一归属时待人工选择，不整批移动所有 default 知识。
5. 为新表、ID 映射、历史修订与文件做一致备份，回退通过备份恢复；解除/删除遵守引用保留规则。

## 10. 验收用例

1. 同一原著一次提炼，故事 A/B 绑定后各自有独立知识 ID，引用同一不可变原文。
2. A 修改角色、删除条目，B 与公共源不变；重绑、刷新、重建索引不复活被删设定。
3. 未绑定某资料的故事 C 不从 RAG、实体直接注入或图谱获得它；人工项目资料列表仍可浏览。
4. 两部原著同名角色不会被错误合并，关系端点和别名属于正确副本。
5. ＋资料默认知识在当前故事可用，同故事多会话共享；显式 project 才共享；分支启用后故事资料按提交分支固定，不影响旁支。
6. 从 A 发起 story 导入，切到 B 后仍归 A；project 导入仍只写项目；提炼失败、重试、解除并发不会串目标或重复复制。
7. 源资料修正或归档后 A/B 的固定版本仍能读取，编辑后的故事事实在实际上下文中优先且能说明原著差异。
8. 删除 A/解除 A 的资料不损坏 B、公共原文、已保存正文和旁支历史。
9. 已有故事只复制 core 的旧操作不能冒充完整资料副本；所有知识类别、证据和关系均覆盖。
10. 新建/旧故事添加资料使用同一幂等服务；迁移保留用户改动，未确定归属的历史知识不被自动共享。

使用离线事务与上下文证据测试加 Vue/API 端到端验证。模型抽检可补充生成体验，不能代替读取集合的隔离断言。

## 12. 本轮实现约束与复核

- 故事副本与世界线均需可由普通 UI 完成闭环，不能只提供存储表/内部 API。未来 L4 的自动更新、跨线合并不在本轮。
- 保留另一窗口全部未提交修改；新增 migration 从 021 起按实际顺序分配，不能改历史 migration。当前工作区基线见 work/implementation-baseline（仅审查临时文件）。
- 不直接操作用户实际资料库来迁移验证；离线测试使用隔离工作区，线上库仅在应用正常升级时执行连续迁移。
- 原文不参与写作是产品约束，不能靠冻结/过滤原文去重新开启它。
- 旧故事 legacy 读取模式必须明确标注；启用独立副本/分支前，确定其公共知识基线并形成不可变副本，不允许静默丢失此前引用内容。

### 12.1 2026-09-08 实现复核补充

- 存量故事允许明确选择“不使用任何公共资料”，确认后保留故事自有知识并切换到严格模式。空选择仍需要用户明确确认；批量绑定与模式切换在同一事务中完成。
- 资料归档是用户的明确选择，自动整理资料列表不能在下一次读取时把同一来源重新创建为活动资料库。
- 发布版本以服务端实际快照计算内容摘要，只包含已确认且归属正确的项目知识；指定了不存在或不符合条件的知识 ID 时应明确拒绝，不能悄悄发布残缺版本。
- 导入文件的容器哈希与可读正文哈希分开保存和校验。例如粘贴资料序列化为 JSON 后，JSON 文件摘要不能冒充解析后正文摘要。历史原文按来源修订保存，缺失或不完整的内容明确标注，不能回退到活动文件冒充旧版本。
- 复制整个故事时，世界线、会话、正文、章节资产、绑定和私有知识身份全部重映射；公共不可变资料版本可以复用。不得留下指向源故事分支的可变记录。

### 12.2 实现后的使用规则

| 用户操作 | 保存位置及生效方式 |
|---|---|
| 在对话点“＋资料”，保留默认范围 | 原文归当前故事及会话所属世界线；自动提炼，已确认知识供该线后续会话使用 |
| 在“＋资料”明确选择整个项目 | 原文和提炼知识归项目公共资料；当前故事也需显式使用其发布版本 |
| 在资料库导入文件或粘贴 | 固定项目公共资料；自动提炼，单纯导入不会绑定所有故事 |
| 对公共资料点“用于当前故事” | 从固定发布版本复制已确认知识到当前故事/世界线，不再次提炼 |
| 编辑故事副本 | 只影响该故事当前线，保留来源身份；不写回公共资料或其他故事 |
| 公共资料产生新版本 | 展示更新提示并允许查阅固定来源；本轮不自动升级现有绑定 |
| 解除使用或归档公共资料 | 保留原文、历史和已保存正文；解除使当前线停止使用该绑定，归档不使已有副本失效 |

发布快照保存实际来源内容及其 hash、实体端点和别名，不依赖公共源当前行仍然存在。故事副本中的时序后继、实体、图边和证据引用一并映射到正确身份；不能因为旧字段缺少 `version_scope` 就复制出冲突实体。

旧故事支持一次性选择多份公共资料，也支持明确“不使用公共资料”。模式切换与绑定同事务提交；确认前保持兼容读取并禁止创建世界线。新建项目的默认故事与新建故事均从严格模式开始。升级前自动备份数据库；本轮验证在隔离数据库中执行，不主动迁移用户正在使用的数据。
