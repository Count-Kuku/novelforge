# NovelForge 对话式创作体验升级计划

本文档记录 NovelForge 从“页面/表单驱动的写作工作台”升级为“对话驱动、资料即用、知识可维护的创作工作台”的实施路线。长期架构边界仍以 [project.md](../project.md) 为准，数据库权威边界以 [storage_architecture.md](../storage_architecture.md) 为准。

## 目标体验

新用户完成模型接入后，应能够：

1. 新建项目，在自由创作中直接拖入原作或参考资料。
2. 使用系统推荐方案开始创作，不需要理解切分、提取模式、检索参数或提示词选项。
3. 在资料结构化整理完成前，先使用已经解析和索引的原文开始写作。
4. 在对话中用自然语言执行“写作、查资料、提炼设定、纠正知识、调整配置”等动作。
5. 浏览、搜索并修改角色、世界观、时间线、关系和来源资料，不接触原始 JSON。
6. 对任何持久化变更查看差异、来源和影响范围，并能够通过新修订撤销。

## 产品原则

- 对话是默认入口，专业页面是检查、批量操作和高级维护入口。
- 自动化不等于静默修改。配置、知识和外部调用必须有作用域、审计和必要确认。
- 原文先可用，结构化知识后完善；长任务不阻塞创作。
- SQLite 继续作为结构化权威来源，现有资料任务、知识修订和自由创作分支模型不推倒重写。
- 正文草稿和工具型消息保持不同语义，避免破坏现有片段接受、重写和分支契约。
- 能力降级必须可见。语义向量不可用时明确使用关键词检索，不能伪装为混合检索。

## 阶段 0：正确性、能力就绪和一致性

目标：先保证系统展示的能力与真实运行能力一致，为后续对话式入口提供可靠底座。

### 交付范围

- 自由创作的 `drafting` 检索覆盖世界观、时间线、地点、组织、道具和能力等正式知识。
- `CreativeProfile.reference_strength/reference_focus` 真正参与检索参数解析。
- 模型档案显式保存 Embedding 模式：关闭、同服务、独立服务、本地。
- Chat 与 Embedding 分开验证和展示；项目首页和模型页显示当前就绪/降级状态。
- 未配置聊天能力时，在创建自由创作会话或需要模型的资料任务前失败，不留下空会话或无意义失败任务。
- 向量被关闭或构建失败时，检索健康报告明确区分“用户关闭”和“异常失败”。
- 修复 DB-first 模式下创作配置已保存却仍被判断为未配置的问题。
- 关系知识的图边改为幂等投影：读取类型化字段，更新前替换旧边，删除/改名/移动分类后不保留活动旧边。

### 验收条件

- 普通世界规则和时间事件能够被自由创作 `drafting` Profile 召回。
- “严格原作/强参考/重点时间线”等配置会改变实际检索模式、数量或来源范围。
- Chat 可用而 Embedding 关闭/失败时仍可创作，UI 明确显示关键词检索。
- 缺少 API Key 时不会新增自由创作会话，也不会创建需要 LLM 的资料任务。
- DB-only 保存创作配置后，侧栏不再误报未配置。
- 关系改名、删除或移动分类后不存在同一知识产生的旧活动边；关系类型来自类型化字段。

## 阶段 1：资料即创作

目标：让用户不离开自由创作页面即可导入资料并开始写作。

### 交付范围

- 自由创作输入区增加附件和资料托盘，支持多文件、粘贴长文、URL 和选择已有资料。
- 附件作用域支持“仅本轮、当前会话、当前故事、整个项目”。
- 复用现有文档解析、切分、来源修订和可恢复资料任务，不创建第二套导入实现。
- 同人资料预设默认建立覆盖全部所选片段的后台计划；只有费用或调用量越过阈值时确认一次。
- 原文完成解析和词法索引后即可写作，知识提取、整理和审核在后台继续。
- 对话中展示“原文可检索、知识提取中、待审核、处理失败”等渐进状态。
- 扫描 PDF 提供显式、可关闭的 OCR 作业与页级置信度预览。

### 验收条件

- 新用户从自由创作拖入资料后，三次以内显式操作即可开始写作。
- 不要求填写标题、切分上限、提取分类等高级参数。
- 刷新或重启后，会话/故事/项目附件作用域和后台任务状态可恢复。
- 相同附件重复提交不会产生重复来源修订或重复任务。

## 阶段 2：统一对话动作协议

目标：自由创作输入不再只代表“生成正文”，而是成为安全、可审计的创作命令入口。

### 建议持久模型

通过连续 migration 增加独立消息与动作记录，例如：

- `creative_messages`：用户消息、普通助手回复、动作回执。
- `creative_action_runs`：动作计划、状态、确认、幂等键和结果。
- `creative_attachments`：消息/会话与来源修订的关联。
- `creative_config_revisions`：本轮、会话和故事配置补丁及撤销记录。

现有 `creative_turns/creative_fragments` 继续只承载正文生成、分支和接受语义。

### 支持意图

- `write`
- `revise`
- `import_sources`
- `extract_knowledge`
- `query_knowledge`
- `update_knowledge`
- `update_config`
- `save_chapter`
- `clarify`

### 安全契约

- 确定性规则优先识别附件和明确动词；结构化 LLM 路由只补充歧义判断。
- 每个动作包含作用域、目标、补丁、是否确认、幂等键和可撤销信息。
- 持久配置、知识覆盖、外部调用和高费用任务先显示动作卡或差异卡。
- 普通模型正文不得直接执行数据库写入。

## 阶段 3：统一资料与知识中心

目标：用户可以像浏览资料库一样查找、打开和修改任何已有知识。

### 交付范围

- 跨分类、来源、世界线和故事作用域的 SQLite FTS 搜索。
- 游标分页或虚拟化，避免一次创建大量 Streamlit 控件。
- “全部、角色、世界观、时间线、关系、地点与组织、来源、待审核、归档”统一视图。
- 卡片/表格列表与详情抽屉；一次点击进入规范表单编辑。
- 普通路径新增、编辑、移动、删除、合并均不暴露 JSON。
- 来源原文精确高亮、知识修订差异和“恢复为新修订”。
- 单条知识保存后立即提交事务，检索索引采用增量后台更新并显示状态。

### 性能目标

- 10,000 条正式/待审核知识时，跨分类搜索 p95 小于 300ms。
- 页面不一次渲染全部条目。
- 单条保存后 500ms 内给出事务提交反馈；索引更新失败可重试。

## 阶段 4：实体视图和视觉体验

目标：让世界观信息以创作者熟悉的方式呈现，而不是数据库记录列表。

### 交付范围

- 角色中心：角色、关系、能力、道具、参与事件和来源。
- 世界观中心：规则、地点、组织、力量体系和冲突。
- 可排序、可筛选的时间轴。
- 关系图浏览与编辑。
- 聚合卡片由权威知识实时投影；卡片编辑回写对应知识修订，不保存会漂移的第二份事实。
- 统一状态徽章、来源 chips、风险颜色、空状态、主操作和后台任务反馈。
- 自由创作固定输入区、可折叠资料抽屉、快捷键和命令面板。
- 技术 JSON 仅在开发者模式显示。

## 阶段 5：自动配置与能力编排

目标：在安全、可解释的前提下接近“只设置模型接入，其余由对话自动调整”。

### 交付范围

- `CapabilityRegistry` 分别管理 Chat、Embedding、Search、OCR 等能力。
- 每个工作流通过 `OperationRequirements` 声明必需能力和允许降级。
- 供应商适配器支持模型发现、能力协商、版本化预设和失效提示。
- 根据用户目标、资料规模、历史费用和质量反馈自动选择检索深度、提取分类、上下文预算和批量大小。
- 自动配置保存“为何调整”和前后差异，用户明确锁定的设置不能被覆盖。
- API Key 迁移到系统凭据管理器；数据库只保存凭据引用、指纹和末四位。

## 跨阶段验证矩阵

每个阶段除现有包结构、DB、检索和应用冒烟验证外，还需逐步增加：

- 首次使用与模型能力就绪验证。
- 自由创作世界观/时间线召回验证。
- 对话附件作用域和重启恢复验证。
- 对话配置补丁、确认、撤销和幂等验证。
- 对话知识查询、修改、证据和修订验证。
- 关系图投影完整性验证。
- 大型知识库搜索和分页性能基准。

## 实施状态

- 阶段 0：已实现，包含检索正确性、模型能力就绪与显式降级、DB-first 配置判断、任务前置校验和关系图幂等投影；以阶段 0 验证脚本及现有回归套件作为交付门槛。
- 阶段 1：已实现。自由创作资料托盘支持多文件、粘贴长文、公开静态网页和选择已有检索资料；附件可按仅下一轮、当前创作、当前故事或整个项目持久隔离；原文解析后立即进入词法检索；同内容同作用域重复提交保持幂等。系统默认复用长资料批次与可恢复任务，对全部片段安排后台知识提取，超过既有 Token/费用阈值时只确认一次；附件卡片从权威任务状态投影“原文可检索、知识提取中、整理完成、处理失败”。扫描 PDF 的本地 OCR 默认关闭，只有用户显式开启且 Tesseract 能力就绪时执行，并保存逐页置信度；能力缺失不阻塞文本层导入。
- 阶段 2：已实现。自由创作输入采用确定性命令优先的动作路由，支持 `write/revise/import_sources/extract_knowledge/query_knowledge/update_knowledge/update_config/save_chapter/clarify`；正文分支继续只由 `creative_turns/creative_fragments` 承载，普通消息和工具回执进入独立消息表。动作计划持久保存目标、作用域、补丁、确认状态、幂等键、结果和撤销快照；配置、知识覆盖、提炼与章节保存均先展示动作卡，确认前无副作用，配置与知识更新可通过新动作撤销。
- 阶段 3：已实现。资料中心新增统一 FTS 视图，覆盖全部、角色、世界观、时间线、关系、地点与组织、来源、待审核和归档；支持故事/世界线过滤、稳定游标分页、列表与详情双栏、来源原文高亮、证据锚点、修订差异和“恢复为新修订”。普通新增、编辑、移动、归档与合并均使用规范表单；单条知识事务不再同步重建整库检索，而由持久增量任务和后台调度器更新索引、展示状态并支持失败重试。10,000 条正式/待审核知识基准中搜索 p95 低于 300ms，单条提交反馈低于 500ms。
- 阶段 4：已实现。资料管理新增创作实体入口：角色中心实时聚合角色、关系、能力、道具、参与事件、对白风格、硬约束与来源；世界观中心按规则、地点、组织、力量体系、物品和约束聚合，并提示关联事件与冲突；时间轴支持参与者、地点、关键词筛选和自然顺序/倒序/新修订排序；关系图从 `graph_nodes/graph_edges` 权威投影浏览，并通过关系表单新增或修订正式关系知识。实体卡不再作为独立检索事实保存，旧卡只保留兼容读取；所有卡片编辑均写回正式知识并追加修订。状态徽章、来源 chips、风险颜色与空状态已统一；自由创作输入区固定在视口底部，资料抽屉保持可折叠，新增命令面板及 Ctrl/⌘+Enter 快捷执行；原始 JSON、技术回执和修订 diff 默认隐藏，仅 `NOVELFORGE_DEVELOPER_MODE=1` 时显示。
- 阶段 5：已实现。新增统一 `CapabilityRegistry`，独立探测 Chat、Embedding、Search、OCR，并由 `OperationRequirements` 为创作、资料导入、知识查询、网络研究和 OCR 声明必需能力、可选能力及可见降级；供应商适配器提供版本化预设、OpenAI 兼容模型发现、能力协商和配置失效提示。创作与资料流程会按目标、资料规模、历史 Token/费用和检索反馈自动选择检索深度、候选数、提取类别、上下文预算与批量大小；每次变化保存原因、信号、前后差异和修订，用户锁定字段永不被覆盖。模型、向量和 Brave Search 密钥已迁移到 Windows Credential Manager 或系统 keyring，SQLite 与配置镜像只保存凭据引用、SHA-256 指纹和末四位，旧 `.env` 密钥会在迁移后清空。
