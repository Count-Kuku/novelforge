# NovelForge UI 全面重构规划

## 1. 重构目标

这次重构不改变现有业务能力和数据模型，重点解决以下体验问题：

- 用户进入页面后无法快速判断“现在应该做什么”。
- 创建、处理中、审核、维护和调试功能混在同一条长页面中。
- 页面层级依赖大量标题、横向单选和嵌套折叠面板，浏览成本高。
- 主操作与 Token、费用、处理范围等重要后果分离。
- 大量多选标签、原始 JSON、内部 ID 和 Worker 信息直接暴露给普通用户。
- 不同页面的标题、留白、按钮高度、列对齐、空状态和反馈方式不一致。
- 窄屏下横向标签、指标卡和多列表单缺少稳定的降级规则。

重构后的判断标准：用户不阅读项目文档，也能从页面标题、当前状态、主按钮和结果反馈完成常见任务。

## 2. 全局设计原则

### 2.1 一页一个主要目标

- 页面只保留一个最重要的主操作。
- 创建、查看进度、审核和维护分别进入独立视图。
- 原始数据、调试信息、批量策略和危险操作统一放入“高级”或“维护”区域。

### 2.2 渐进披露

- 首屏只展示当前状态、必要输入和下一步。
- 推荐值直接生效，不要求新用户先理解全部参数。
- 高级参数最多通过一次展开即可访问，不使用多层嵌套折叠。

### 2.3 后果紧邻操作

- Token、费用、调用次数、处理数量和保存位置必须显示在主按钮上方。
- 详细估算可以折叠，但摘要始终可见。
- “预计”与“实际”使用不同文案，避免用户误认为预计值是账单。

### 2.4 内容优先

- 长列表使用表格、分页、范围选择或主从详情，不使用几十个已选标签。
- 编辑器旁显示必要上下文；证据、修订和元数据作为详情页签。
- 空状态提供原因和唯一推荐动作，不展示无意义的空控件。

### 2.5 一致与可访问

- 统一 8px 基础间距、控件高度、圆角、边框、焦点态和状态颜色。
- 状态不只依靠颜色，始终配套文字。
- 桌面端列对齐；窄屏自动堆叠；标签栏可横向滚动。
- 主按钮、次按钮、危险按钮和禁用按钮拥有稳定视觉语义。

## 3. 信息架构

### 3.1 全局导航

| 工作区 | 页面 | 用户目标 |
| --- | --- | --- |
| 工作台 | 项目总览、项目资源 | 判断进度、找到内容 |
| 资料 | 资料导入、核心设定、检索中心 | 导入、审核、维护、查询资料 |
| 规划 | 创作配置、全书大纲、分卷、剧情段、章节细纲 | 从方向逐层拆解到章节 |
| 写作 | 自由创作、正文生成、章节评价 | 生成、迭代、审阅正文 |
| 配置 | 模型配置、生成规则、写作偏好 | 调整系统级配置 |

侧栏只负责项目、故事和页面切换；项目统计和用量改为紧凑摘要，避免与页面内容竞争。

### 3.2 资料中心

资料导入页按生命周期重组为五个工作区：

1. **概览**：只展示当前状态和最需要完成的一件事。
2. **导入**：创建新导入，文件上传与文本粘贴共用同一套默认展开的处理流程。
3. **处理**：查看后台任务和长篇批次。
4. **审核**：审核候选知识和查看审核记录。
5. **管理**：按原文资料、知识条目、健康检查和资料包管理结果。

本地资料导入统一为四步：选择方案 → 添加资料 → 检查切分 → 确认处理。上传文件和粘贴文本只属于不同输入方式，不再分成两个入口；短文本自动作为单片段处理。流程摘要始终可见，整个导入表单不使用折叠栏；只有低频参数和高级操作按需折叠。

### 3.3 检索中心

- **查找资料**：查询、结果和反馈。
- **质量评估**：固定测试集和检索效果分析。
- **索引维护**：健康检查、重建和来源文件维护。

### 3.4 核心设定、规则和偏好

- 核心设定只管理高优先级事实。
- 生成规则只管理不可违背的边界。
- 写作偏好只管理可开关的表达倾向。
- 模型配置不再嵌入故事管理页。

### 3.5 规划与写作

- 规划页统一采用“输入定位 → 讨论 → 生成编辑 → 结果依据”的节奏。
- 正文页统一采用“细纲 → 写作 → 审阅整理”的节奏。
- 自由创作保持“内容 → 操作 → 下一轮输入 → 辅助整理”的顺序。

## 4. 统一组件

- 紧凑页头：页面名称、用途和项目上下文。
- 区块标题：标题、说明和一致间距。
- 状态条：最多展示 4～6 个关键指标。
- 步骤标题：明确当前步骤及其目的。
- 操作摘要：在主按钮旁显示范围、Token、费用和保存结果。
- 空状态：解释原因并给出单一下一步。
- 主从布局：列表与详情并排，窄屏自动堆叠。
- 危险操作区：与日常操作视觉隔离，并要求明确确认。

## 5. 页面审查结果与改造重点

| 页面 | 主要问题 | 改造重点 |
| --- | --- | --- |
| 项目总览 | 快捷入口和指标数量偏多 | 强化推荐下一步，次要指标折叠 |
| 项目资源 | 筛选和详情边界不明显 | 统一主从布局、空状态和详情标题 |
| 资料导入 | 七类工作混在一页 | 拆成五个工作区和四步导入 |
| 长篇批次 | 任务恢复、专项提取、计划和整理连续堆叠 | 以任务状态和操作类型分区 |
| 待审核知识 | 批处理、质检、筛选、编辑和原始数据混杂 | 先筛选列表，再编辑详情；策略单独放置 |
| 正式知识库 | 分类、实体卡、合并、删除和 JSON 编辑混杂 | 分类列表、条目详情、维护工具分层 |
| 核心设定 | 故事管理中嵌入模型配置 | 移除跨职责内容，保留跳转入口 |
| 检索中心 | 查询、评估、健康和重建全部连续显示 | 拆成查找、评估、维护三个视图 |
| 创作配置 | 对话和大型表单连续显示 | 默认对话引导，手动配置作为第二视图 |
| 各级大纲 | 输入、讨论、生成和库存边界不一致 | 统一四段流程和区块标题 |
| 正文生成 | 多套自动流程按钮并列 | 明确单章主流程，高级自动化后置 |
| 章节评价 | 输入和长报告连续堆叠 | 输入与结果分视图，结果优先展示结论 |
| 生成规则 | 快速记录与三层规则编辑竞争 | 快速记录为主，规则库分层管理 |
| 写作偏好 | 五个页签认知负担高 | 常用管理、创建、预设、预览重新分组 |
| 模型配置 | 方案管理、表单、价格和用量连续堆叠 | 当前方案、已保存方案、用量分视图 |

## 6. 验收标准

- 每个页面首屏都能看到用途和主要操作方向。
- 同一视图最多一个主按钮；并列按钮有明确主次。
- 所有模型调用在按钮附近显示 Token/费用摘要。
- 大于 20 项的选择不以默认全选标签形式展示。
- 普通流程不显示原始 JSON、内部 ID、租约或 Worker 术语。
- 桌面端同一行控件高度和底边对齐；窄屏自动堆叠。
- 所有空列表都有清晰空状态。
- 全部 UI 自动化检查通过，关键页面完成浏览器桌面与窄屏视觉检查。

## 7. 后续 Vue 迁移边界

本轮先完成 Streamlit 的信息架构和设计系统重构。资料导入、任务、待审核和知识库会按照独立工作区拆分，使其未来能够逐个映射为 API 与 Vue 路由；不会在本轮同时维护两套不完整前端。

## 8. 本轮实施结果

- 已用新的紧凑页头、统一间距、状态条、步骤标题、空状态和操作摘要替换旧全局样式。
- 已重写侧栏名称、图标、说明和项目/故事切换区，同时保留原内部路由以兼容已有逻辑。
- 已完成资料中心五工作区、长篇导入四步流程、长篇批次单任务视图、待审核分视图与知识库分层管理。
- 已将 Token、费用、模型调用次数和处理范围的摘要放到主操作直接上方。
- 已把检索、创作方向、全书大纲、章节写作、章节审阅、生成规则和模型配置拆成目标明确的分步或分视图界面。
- 已把全部旧 `use_container_width` 用法更新为新宽度 API，并补齐分段导航的明确选中态和窄屏换行。
- 已新增全页面 UI 验收脚本，覆盖 16 个导航页和有真实批次数据的长篇批次工作区。
- 自动化回归共 40 个可执行验证脚本全部通过；浏览器验收覆盖桌面、760px 和 390px 宽度，未发现控制台错误。
